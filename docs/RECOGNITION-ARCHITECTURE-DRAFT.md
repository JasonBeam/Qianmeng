# 通用动态识别系统草案

状态：未实现。此草案记录后续方向，不表示当前版本具有完整的通用游戏识别能力。

## 分层

1. **感知**：在本机读取获得授权的前台进程标识、窗口状态和系统资源信号。不截屏、不做 OCR、不读取窗口文档内容。
2. **识别**：将信号归一化为应用类别、场景和有限事件；通用识别先覆盖“游戏/工作/媒体/空闲”，特定应用使用独立适配器。
3. **决策**：根据本地偏好、隐私模式和当前活动策略决定是否响应。
4. **反馈**：以桌宠动作、文字或声音反馈；用户可暂停、静音或关闭识别。

## 扩展边界

适配器只接收声明过的本地数据，并输出版本化的归一化事件。默认不启用网络采集；确有本机应用 API 的适配器应单独说明权限、数据流和关闭方式。适配器不得执行任意脚本、读取屏幕或上传用户状态。

实现时应先提供通用应用识别，再逐个增加可选适配器，并为隐私模式、适配器启停、误识别和资源开销建立验收。动作质量验收仍是此工作之前的门槛。
